# Complete research transport resource audit

This maps the actual `sc64-transport-abort` component assembly: decoder,
compositor, dictionary/canvas adapter, three-client fair mux, two DMA channels,
two 64-byte queues, cancellation/retirement logic, and stock arbiter/SDRAM
controller. Observation and stimulus ports stay accessible. This is a resource
audit of a research pipeline, not a complete SC64 product or a hardware fit.

## Reproduce

```powershell
docker run --rm -v "${PWD}:/repo" sc64-open:diagnostic-lpf /usr/bin/python3 -B /repo/vendor/sc64/tests/gif/transport-fit/run.py /repo/build/sc64-transport-fit/repeat --decoder /repo/build/sc64-bounded/agent-core --mux /repo/build/sc64-transport-mux/proof2/gif_transport_mux.sv
docker run --rm -v "${PWD}:/repo" sc64-open:diagnostic-lpf /usr/bin/python3 -B /repo/vendor/sc64/tests/gif/transport-fit/run.py /repo/build/sc64-transport-fit/stock-repeat --stock
```

The bounded core comes from [sc64-bounded](../sc64-bounded/README.md); the mux
comes from [transport-mux](../transport-mux/README.md). Generate and functionally
verify those candidates using their owning tests before treating them as
qualified functionality. This runner records the exact input hashes, mapped
top ports, all inferred memories and physical RAM parameters. It uses sv2v and
`synth_lattice -family xo2`, with no missing primitive black boxes or weakened
memory collision flag. Unreviewed mapped cell types fail explicitly.

Six pipeline and four mux `$fatal` checks are simulation-only. The runner
requires those exact counts, replaces them with empty statements in generated
copies, and records their texts and original hashes. No functional control
assignments are removed. This does **not** implement their runtime error
handling in hardware; the owning functional tests remain necessary.

## Measured combined results

| Assembly | LUT4 | CCU2D | FF | DP8KC | Distributed 16x4 RAM |
| --- | ---: | ---: | ---: | ---: | ---: |
| Original cached/abort transport | 7,178 | 4,206 | 1,203 | 7 | 16 |
| Bounded 512-byte stack, original mux | 6,991 | 4,205 | 1,203 | 4 | 16 |
| Bounded stack and proven fair mux | 2,381 | 413 | 1,203 | 4 | 16 |
| Stock arbiter/SDRAM boundary only | 332 | 10 | 150 | 0 | 0 |

Evidence: `build/sc64-transport-fit/{baseline-measured,bounded-original-mux,
frozen,stock-reference}/`. These are actual combined syntheses, not sums of
standalone decoder/compositor reports. Global optimization and autogenerated
cell names make `owner_cells` partial attribution, not independent additive
component budgets.

The original mux's `(int'(next_owner)+offset)%3` dominates the first result:
4,919 LUT4 and 3,776 carry cells have mux-prefixed names. The proof-backed
explicit round-robin mux removes that wide modulo implementation. Counting
only decoder and compositor misses this major problem.

The bounded decoder exposes no spill interface. Its maximum-output guard and
phrase-bound evidence replace the earlier spill proposal for this supported
320x240 class. Canvas, dictionary backing, compressed windows and output
packets remain external SDRAM; no local full-frame buffer is hidden here.

Stock already uses 22 of 26 EBRs (18 DP8KC plus four existing FIFO8KBs after
packing). The measured four additional EBRs consume all remaining blocks.
Do not add another arbiter or SDRAM controller to stock: those included in
this wrapper are existing reuse boundaries. Conversely, source/output
`memory_dma` instances are **two additional channels**, not the existing
USB/SD channels, which enter this wrapper as independent memory clients.

The research mux occupies the CFG memory-client slot. It does not preserve an
independent original MCU CFG-memory client. Production integration must add
that arbitration/ownership, job registers and bounded arena lifecycle; these
are not included in the current count. Verification/bypass ports and broad
observation ports also retain research logic that could change in a real
integration. No exact production incremental count follows from subtraction.

## Actual MachXO2 packing and remaining logic gap

The pinned MachXO2 `pack.cc::print_logic_usage` adds two LUT units per CCU2D
and four RAM plus two RAM-write units per distributed RAM. This is checked
against the actual MachXO2 packer, not inferred from another FPGA family.
Its prepack result is exactly `2381 + 2*413 + 6*16 = 3303`.

The same executable's fixed stock diagnostic (`build/sc64-dma-flags/baseline/
route.log`) reports 5300 prepack LUT units from 4448 LUT4, 402 CCU2D and eight
distributed RAMs, and 5591 packed TRELLIS_COMB cells. Both use the same mapped
cell vocabulary and Yosys image. A rough stitched prepack estimate is
`5300 + 3303 - (332 + 2*10) = 8251`, above 6864 available units. This is a
warning to integrate and optimize, **not a formal lower bound or exact fit
result**: cross-boundary optimization and research ports affect the totals.

The simulation-driven SDRAM DQ wrapper is rejected by the real packer as an
unsupported tristate pattern (`pack-tristate-rejected`, packer exit 125).
`--physical-dq` substitutes only the testbench DQ driver/observation wiring
with a true bidirectional top-level DQ pad, retaining the stock controller.
That variant maps to 2343 LUT4, 413 CCU2D and the same RAM/FF counts.

```powershell
docker run --rm -v "${PWD}:/repo" sc64-open:diagnostic-lpf /usr/bin/python3 -B /repo/vendor/sc64/tests/gif/transport-fit/run.py /repo/build/sc64-transport-fit/physical-repeat --decoder /repo/build/sc64-bounded/agent-core --mux /repo/build/sc64-transport-mux/proof2/gif_transport_mux.sv --physical-dq
docker run --rm -v "${PWD}:/repo" sc64-open:diagnostic-lpf /usr/bin/python3 -B /repo/vendor/sc64/tests/gif/transport-fit/pack.py /repo/build/sc64-transport-fit/physical-repeat/mapped.json /repo/build/sc64-open-timing-options/nextpnr-machxo2 /repo/build/sc64-transport-fit/pack-repeat
```

The real packer succeeds, yielding **3521 TRELLIS_COMB, 1203 FF, four DP8KC,
16 RAMW and 739 I/O cells**. The observation interface exceeds the device's
336 I/O sites and is not a board pinout. `pack.py` therefore reports
`fit_demonstrated=false` and always returns 3 for successful-but-unqualified
packing. It never requests placement, routing, configuration or a bitstream.
Unplaced-cell warnings are expected; packing success is not physical fit.
Exact executable hash and cell counts are in `pack-frozen/result.json`.

The initial `baseline` run fails on remaining mux simulation `$finish`; the
next `baseline-final` run fails while serializing unprocessed library modules.
Neither is a pass. The corrected runner inventories/removes all ten assertions
and exports only the selected top at the memory checkpoint.

Four remaining EBRs suffice for this bounded pipeline, but combined logic,
preserved MCU arbitration, actual integration, placement and complete timing
remain open. No firmware, cart state or production RTL changes occur.
