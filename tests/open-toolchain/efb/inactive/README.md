# Dedicated EFB input ties: routing diagnostic

This opt-in preparation removes 24 logical constant connections that attempt to
drive dedicated pad/PLL paths from fabric. It preserves every other connection,
every cell, and every parameter. It does not synthesize physical replacement
ties, change EFB configuration, or establish electrical equivalence. The existing
EFB configuration-emission barrier remains mandatory.

## Evidence and exact scope

The unchanged SC64 [generated wrapper](../../../../fw/rtl/vendor/lcmxo2/generated/efb_lattice_generated.v)
disables both user I2C peripherals, SPI, and TC, enables UFM, grounds the unused
inputs, and holds UFMSN high. The public Trellis database and actual generated
7000 graph establish different physical paths:

| Ports | Graph evidence | Treatment |
| --- | --- | --- |
| I2C1SCLI/SDAI | Sole fixed inputs from R0C21 JPADDIC/JPADDID | Remove only their exact low simulation ties. |
| SPISCKI/MISOI/MOSII | Sole fixed PIO pad inputs | Remove only exact low ties with user SPI disabled. |
| UFMSN | Sole fixed R27C37 JPADDIA input | Remove only the exact high placeholder, with user SPI disabled and UFM enabled. Preserve UFM parameters and Wishbone traffic. Physical SN behavior still requires board/electrical qualification. |
| PLL0/1 DATI[7:0], ACKI | Fixed PLL feedback or PLL input-mux wires, not ordinary fabric input muxes | Remove exact low placeholders only if all instantiated PLLs explicitly disable PLL_USE_WB and no EFB PLL outputs are connected. |
| I2C2SCLI/SDAI | R1C4 JCLK1/JC0 fabric paths | Preserve. |
| SPISCSN; TCCLKI/TCRSTN/TCIC | Ordinary fabric paths | Preserve. |
| All Wishbone inputs/outputs and WBCUFMIRQ | Actual used interface | Preserve. |

[Lattice's UFM/EFB guide](https://www.latticesemi.com/view_document?document_id=39086)
sections 4, 5, and 11 distinguish primary I2C and SPI dedicated pins from
secondary I2C/fabric chip-select paths; Table 11.1 restricts PLL buses to PLL
components. Section 10.1 conditions ufm_sn operation on UFM and SPI being
enabled, and calls for inactive-high selection when that SPI access is unused.
On stock SC64, pin 70 carries SDRAM_A5; disabled configuration-SPI ownership
and the initial SPI_OFF feature setting must therefore be preserved. The
generated high simulation tie does not imply a physical pull-up. See the
[configuration/board investigation](configuration-research.md). Routing alone
does not certify configuration-port arbitration or hardware behavior.

Pinned source evidence is `database/MachXO2/tiledata/CIB_CFG0/bits.db` in database
commit `015e0330630d7c238c0e4f2cdd9c8157eb78c54a`, generated by the public
[109-efb fuzzer](https://github.com/YosysHQ/prjtrellis/tree/3afe7b52b30f4b4417ee98f03016767a502006e3/fuzzers/machxo2/109-efb).
The NCL template only seeds routing discovery; it is not an independently
implemented SC64 EFB configuration. `graph.py` records every direct upstream
EFB input edge, including fixed/configurable status. PLL0 has fixed feedback
from R1C1 and a named mux input; PLL1 has named mux inputs. This inventory does
not claim the database fully characterizes those muxes. The vendor guide plus
explicitly disabled PLL interfaces justify excluding the unused logical
placeholders only within the guarded diagnostic.

## Reproduce and barriers

Run in the existing combined diagnostic image with the checkout mounted at
`/sc64` and an ignored output directory at `/out`:

```sh
python3 -B /sc64/tests/open-toolchain/efb/inactive/verify.py /sc64 /out/minimal
python3 -B /sc64/tests/open-toolchain/efb/inactive/test.py /out/physical.json
python3 -B /sc64/tests/open-toolchain/efb/inactive/prepare.py \
  /out/physical.json /out/prepared.json --diagnostic
```

`physical.json` is the existing guarded full SC64 synthesis result after the
PLL source-attribute preservation step. Preparation accepts only exact SC64
density/UFM settings, explicitly disabled peripherals, unused peripheral
outputs, and exact constant values. Literal bits or uniquely driven VLO/VHI
nets are accepted. It fails before writing on incompatible inputs and refuses
to overwrite an existing output. This is a separate netlist experiment, not a
change to production RTL or the installed backend patch.

The focused test checks all other cells, attributes, parameters, and connections
against the input. It also rejects 32 mutations: active peripherals, each of
the 24 nonconstant inputs, reversed pad ties, connected peripheral output,
and an enabled PLL Wishbone interface. The minimal driver reruns the original
wrapper baseline, then verifies prepared routing and exact exit-125 normal,
configuration, and saved-setting barriers. Configuration files must remain absent.

No production FPGA image, timing qualification, new license, or hardware action
results from these probes.
